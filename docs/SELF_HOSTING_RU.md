# TRACK DUEL: хостинг ближе к игрокам (5.2)

Клиент игры: https://nasickkk.github.io/track-duel/?v=5.2
WebSocket-релей: `server/index.mjs`. Работает на Node.js 20+. Релей НЕ проверяет попадания и не является авторитетным 128-tick игровым сервером.

## Что изменилось в сети

- Локальная физика в браузере: фиксированный шаг **128 Гц** (с ограничением catch-up при падении FPS).
- Позиции: до **64 пакетов/с**, но ограничены частотой рендеринга и сетью.
- Сводка HP и счёта: до **30 пакетов/с** от хоста.
- RTT на HUD: `RTT сервер` — круговой запрос до WebSocket-хоста; `RTT друг` — круговой запрос туда-обратно между клиентами (через релей, если он выбран). RTT не равно односторонней задержке.
- При выстреле авика трассер начинается с визуально смещённого дула; виден дольше.
- Сервер увеличил лимит приёма сообщений с 100 до 220/с на клиента, отвечает `{t:"pong",id}` на `{t:"ping",id}`.

**Важно:** расчёт попаданий пока происходит в браузере хоста и зависит от доставки координат. 128 Гц локальной физики **не означает 128 Hz серверных тиков**. Для соревнований нужно переписать сетевую архитектуру: сервер-авторитет, timestamped input, лаг-компенсация, client prediction/interpolation и валидация выстрелов.

## Вариант 1. На своём компьютере Windows

1. Установить Node.js 20+ с https://nodejs.org.
2. Скачать ZIP репозитория (GitHub → Code → Download ZIP), распаковать, открыть папку `server`.
3. Дважды щёлкнуть **start-windows.bat**. Скрипт проверит Node, поставит `ws` через npm и запустит релей на порту **10000**.
4. Открыть **http://127.0.0.1:10000/health**. Должно быть `"ok":true`.
5. Этот адрес **не пригоден** для друга за пределами домашней сети или для GitHub Pages: нужен публичный **HTTPS / WSS** адрес, домен, TLS и доступ снаружи.
6. Проверить у провайдера, есть ли **публичный IPv4** без CG-NAT. Если есть — настроить DNS (A-запись на свой адрес), проброс **TCP 80/443** на свой компьютер и разрешения в брандмауэре.
7. Установить Caddy (https://caddyserver.com/docs/install), скопировать `server/Caddyfile.example` в `Caddyfile`, заменить `duel.example.com` на свой реальный домен. Запустить `caddy run --config Caddyfile`. Он будет автоматически обслуживать HTTPS/WSS и пересылать запросы в Node на 127.0.0.1:10000.
8. Проверить извне `https://ВАШ-ДОМЕН/health`. В игре выбрать **Через сервер (WebSocket)** и указать `https://ВАШ-ДОМЕН`. Обоим игрокам — одинаковый адрес.

**Защита:** не открывать наружу порт 10000; публиковать только TCP 80/443 через HTTPS. Не отключать проверки TLS и origin в коде. Релей — прототип для друзей, не защищённая публичная платформа. Держать Windows и Node обновлёнными. Не выкладывать домашний IP в открытые группы и не присылать личные ключи/токены.

**Если CG-NAT:** обычный проброс не поможет. Можно воспользоваться Cloudflare Tunnel (поддерживает WebSockets) либо VPS. Туннель тоже может добавить задержку: сравнивайте фактический RTT.

## Вариант 2. Недорогой VPS (РФ/Казахстан)

Ориентиры на ноябрь 2026 — проверяйте цену перед оплатой:

- **FirstVDS** (Москва): от **299 ₽/мес** за 1 vCPU, 1 ГБ RAM, 15 ГБ; 2 ГБ — **519 ₽/мес**. Источник: https://firstvds.ru/docs/tariffs.html
- **Hoster.kz** (Казахстан): **3 100 ₸/мес** за 1 vCPU, 1 ГБ, 25 ГБ NVMe. Источник: https://hoster.kz/cloud/vps/

Для небольшого WebSocket-ретранслятора на 2–4 игрока достаточно стартовой Linux-машины. Для будущего авторитетного 128 Hz сервера и БД разумнее 2 vCPU и 2+ ГБ RAM, нагрузку нужно мерить.

На Ubuntu VPS:
1. Установить Node.js 20+, Git и Caddy официальными инструкциями.
2. `git clone https://github.com/nasickkk/track-duel.git`
3. `cd track-duel/server && npm install --omit=dev`
4. Пробный запуск: `NODE_ENV=production ALLOWED_ORIGIN=https://nasickkk.github.io PORT=10000 node index.mjs`.
5. Проверить `curl http://127.0.0.1:10000/health`. Затем оформить как systemd-службу с отдельным непривилегированным пользователем, чтобы работал после выхода из SSH.
6. Настроить DNS A-запись на VPS, открыть TCP 80/443; Caddy настроить по примеру `server/Caddyfile.example`. Проксировать HTTPS/WSS на localhost:10000.
7. Убедиться, что `https://ВАШ-ДОМЕН/health` доступен обоим игрокам.
8. В игре указать этот адрес вместо Render.

## Как выбрать локацию

Провести три теста **в обоих браузерах**: текущий Render, домашний сервер и VPS в Москве/Казахстане. Во время матча смотреть `RTT сервер` и `RTT друг`. Предпочитать минимальную **большую** задержку из двух игроков, а не только минимальный RTT у владельца сервера. Учитывать колебания RTT, потери пакетов и FPS.

### Ловушка: «128 tick»

Частота локальной физики 128 Гц стабилизирует интеграцию движения, но не сокращает сетевой маршрут. В браузере WebSocket работает поверх TCP и может задерживать новые сообщения из-за потерь/очередей. Для будущей соревновательной версии нужен выделенный сервер с авторитетными хитами и компенсацией задержек. Переход на VPS сам по себе это не реализует.
